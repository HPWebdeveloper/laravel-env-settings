## Partial test doubles — change one setting without restating the rest

Swapping a settings class in a test has meant rebuilding it argument by argument:

```php
$this->app->singleton(AuthSettings::class, fn () => new AuthSettings(
    domain: 'test.example.com',
    redirect_url: 'http://test.example.com/callback',
    timeout: 5,                 // ← the only value the test cares about
    mfa_enabled: false,
));
```

Leaving the others out is not an option:

```
ArgumentCountError: AuthSettings::__construct(): Argument #1 ($domain) not passed
```

So every test repeats every argument — and **adding a property later breaks every test that swaps that class**, none of which cared about the new property. That is a tax on exactly the discipline this package is meant to encourage.

### `fake()`

Start from a real environment and replace only what matters. The result is bound as the container singleton, so `envSettings()`, injection and `app()` all return it:

```php
AuthSettings::fake(['timeout' => 5]);

envSettings(AuthSettings::class)->timeout;   // 5
envSettings(AuthSettings::class)->domain;    // whatever development() resolves to
```

Every unnamed property keeps the value the environment resolves to, so adding a property later leaves the test untouched. Base it on a different environment with `from:`:

```php
AuthSettings::fake(['timeout' => 5], from: 'production');
```

### `from()` and `with()`

The two pieces `fake()` is built from, useful on their own and outside tests:

```php
AuthSettings::from('production');                        // resolve another environment
AuthSettings::from('production')->with(['timeout' => 60]); // a copy, nothing bound
```

`from()` swaps `APP_ENV` and runs the **real** resolution path — `#[Environment]` attributes, `environment_map` and local overrides all included — then restores it, whatever happens. `with()` returns a new instance and leaves the original untouched.

### Design notes

**A typo throws.** Silently changing nothing would leave a test asserting against the environment's real value while believing it had been replaced:

```
InvalidArgumentException: Unknown property on App\Settings\AuthSettings: timout.
Known properties: domain, redirect_url, timeout, mfa_enabled.
```

A wrong type raises a `TypeError` at the `fake()` call rather than wherever the value is later read.

**Copies are cloned, not rebuilt.** A settings class may be subclassed with a different constructor signature — a local override is exactly that — so `new static(...)` would break on any that did. Cloning copies whatever shape the runtime class actually has.

**Calls do not accumulate.** Each `fake()` resolves the base afresh rather than from an instance a previous call bound, so a second `fake()` in the same test starts from the environment again, not from the first.

**`readonly` properties cannot be replaced this way.** Classes generated by `env-settings:make` do not declare any.

### Upgrading

Purely additive — three new methods on `EnvironmentSettings`, nothing existing changed or removed. The explicit `$this->app->singleton(...)` form still works exactly as before, and remains the right choice when a test needs to pin every value.
